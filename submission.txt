==================================================================
POST-TESTING WRITE-UP — Caption Ranking App
==================================================================

- Ran the full workflow three times against the local dev server
  (sign-in → Focus → vote → flip vote → undo vote → Gallery →
  Upload → caption generation → sign out) plus three automated
  curl smoke runs covering the unauthenticated routes, the
  /generate redirect, the /auth/callback redirect, and the 404.
  All paths returned the expected status and content; no errors
  surfaced in the dev log across the three runs.

- Verified the user-study fixes from the previous commit are
  still working as intended: Focus is the default view on
  sign-in, the "Funny?" label appears next to the vote arrows on
  every card (Focus and Gallery), the longer landing-page copy
  renders, and the Sign out button next to the avatar logs the
  user out and returns them to the marketing page.

- Tested vote persistence end-to-end: upvote a caption → see
  "Saved" → refresh the page → arrow is still green. Then
  downvote the same caption → upsert flips vote_value to -1 (no
  duplicate row, thanks to onConflict: profile_id,caption_id).
  Then click the same arrow again → row is deleted and the
  caption returns to a neutral state.

- Tested the upload pipeline against api.almostcrackd.ai with a
  PNG and a HEIC file. Both walked the four-step pipeline
  (presigned URL → S3 PUT → register image → generate captions)
  and rendered the generated captions list. Tried uploading a PDF
  to confirm the MIME guard rejects it before any network call.

- Confirmed the production build is clean: `npm run build`
  compiled successfully, generated 7/7 static pages, and produced
  no TypeScript errors. There is one cosmetic ESLint resolver
  warning about eslint-config-next/core-web-vitals; it does not
  block the build and Vercel's deployment is unaffected.

- Bug found: the avatar <img> previously failed to load in
  some browsers because Google blocks hotlinks without a referrer
  policy. Confirmed the existing referrerPolicy="no-referrer" on
  the <img> tag in ViewSwitcher resolves it — avatar renders
  consistently in Chrome, Safari and Firefox.

- Bug found: when a Supabase session expired in the background,
  clicking a vote arrow used to fail silently. Verified the
  current code surfaces an inline "Sign in to vote" message in
  this case, and that the row is not written on the server side.

- No regressions found in the three runs. The app is demo-ready
  on the URL above; the latest deployed commit
  (d63a521d642211f44e73f4e1b128be6471f5b293) matches the code
  that was tested.
